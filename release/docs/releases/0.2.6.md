## Recovery observations

- Some immediate post-dispatch API responses did not yet contain the expected
  run identity. Resuming the saved record accepted the same run IDs after the
  metadata settled; no additional dispatch was necessary.
- Windows promotion needed [the run-name correction](https://github.com/HolderTeam/holder/pull/445).
- Two Kit macOS jobs were cancelled before execution because GitHub could not
  assign a hosted runner. A failed-jobs retry retained successful jobs and
  completed preparation on attempt 2.
- SDK publication first created an empty draft and stopped during its destination
  recheck. After observing the failed attempt in the record, a targeted retry
  completed publication against that draft and the same pinned archives.
- Daemon and Kit Ubuntu builds initially waited for core packages. The maintainer
  retried the four builds once core became available.

Interactive platform checks and upgrade coverage remain separate work in
[#131](https://github.com/HolderTeam/holder/issues/131),
[#132](https://github.com/HolderTeam/holder/issues/132) and
[#196](https://github.com/HolderTeam/holder/issues/196).
